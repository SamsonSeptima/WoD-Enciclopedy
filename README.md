# Миры Тьмы — энциклопедия World of Darkness

Единый статический репозиторий-энциклопедия: корневая страница «Миры Тьмы» и два самостоятельных тома — **Demon: The Fallen** и **Hunter: The Reckoning 5e**.

Всё работает офлайн: HTML, CSS и JavaScript, без сборщика, сервера и базы данных. Ссылки между индексом и томами относительные, поэтому энциклопедия одинаково работает локально и на GitHub Pages в подпапке репозитория.

---

## Что внутри

| Часть | Где | Что это |
|---|---|---|
| **Миры Тьмы** | `index.html` | Корневая страница энциклопедии: два тома, быстрый доступ, линейки в работе, палитра и описание проекта |
| **Том I** | `demon-the-fallen/` | «Пепел Небес»: Demon: The Fallen — 52 статьи, 7 Домов, 23 Знания, 115 сил |
| **Том II** | `hunter-the-reckoning/` | «Охота»: Hunter: The Reckoning 5e — 37 статей, 5 Кредо, 7 Драйвов, 14 Граней |

У каждого тома свои стили, поиск, бестиарий, лист персонажа и сохранения в `localStorage`.

## Структура

```text
wod-encyclopedia/
├── index.html                    корневая страница «Миры Тьмы»
├── assets/
│   ├── base.css                  базовая типографика, сетка и карточки томов
│   ├── index.css                 стили корневой страницы
│   ├── favicon.svg
│   ├── fonts/                    Cormorant Garamond + Inter
│   └── img/                      фоны томов
├── .nojekyll                     отключает Jekyll на GitHub Pages
├── .gitignore
├── README.md
├── demon-the-fallen/             Том I
│   ├── index.html
│   ├── assets/
│   ├── content/
│   └── README.md
└── hunter-the-reckoning/         Том II
    ├── index.html
    ├── assets/
    ├── content/
    └── README.md
```

Корневой `index.html` ссылается на `demon-the-fallen/index.html` и `hunter-the-reckoning/index.html`. Тома возвращаются на корневую страницу через `../index.html` — иконкой глобуса в шапке, ссылкой «все миры» в боковой панели и футером. Отдельного портала `world-of-darkness/` больше нет: его роль выполняет корневая страница.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий, например `wod-encyclopedia`.
2. Загрузите **содержимое этой папки** в корень репозитория — не саму папку:
   - `index.html`;
   - `assets/`;
   - `.nojekyll`;
   - `.gitignore`;
   - `README.md`;
   - `demon-the-fallen/`;
   - `hunter-the-reckoning/`.

   В веб-интерфейсе GitHub удобно загружать партиями: корень и assets, затем демоны, затем охотники.
3. **Settings → Pages → Build and deployment**:
   - Source: **Deploy from a branch**;
   - Branch: `main`;
   - Folder: **`/ (root)`**;
   - Save.
4. Через 1–3 минуты откройте:

   ```text
   https://<логин>.github.io/wod-encyclopedia/
   ```

Корневая страница откроется сразу; из неё доступны оба тома.

> **Частая ошибка.** Не загружайте содержимое `hunter-the-reckoning/` в корень репозитория. В корне должен лежать `index.html` из этой папки (`wod-encyclopedia`), а `hunter-the-reckoning/index.html` — внутри своей папки. Если в корень попадёт индекс Охотников, GitHub Pages откроет его как главную страницу, а его `assets/` и `content/` останутся в подпапке — стили и скрипты вернут 404, и страница будет выглядеть «сломанной».

> `.nojekyll` обязателен именно в корне публикуемой папки. Он отключает обработку Jekyll и гарантирует, что все файлы и папки отдаются как есть.

## Локальная проверка

Открывайте именно `index.html` — как корневой, так и в папках томов. В индексе все переходы указывают на `.../index.html`, а не на папки: при открытии через `file://` ссылка на папку не открывает её `index.html` автоматически.

Чтобы проверить энциклопедию в условиях, максимально похожих на GitHub Pages (сайт в подпапке), запустите сервер из **родительской** папки:

```powershell
python -m http.server 8780 --directory D:\Dev
```

И откройте:

```text
http://127.0.0.1:8780/wod-encyclopedia/
```

Проверьте переходы: корневая страница → демоны → «Все миры» → корневая страница → охотники → «Все миры».

## Обновление

Проекты-источники лежат отдельно (`demon-the-fallen`, `hunter-the-reckoning`). После правок скопируйте в этот репозиторий только runtime-файлы:

- `index.html` тома;
- `assets/`;
- `content/` (для томов).

Корневая страница использует собственные `assets/` этого репозитория. Сборка не нужна: `content/*.js` — это уже готовые данные. Если менялась структура ссылок, проверьте относительные пути.

## Что не входит в репозиторий

Сюда намеренно не скопированы:

- `preview/` — скриншоты и превью;
- `sources/` — текстовые выгрузки книг;
- `tools/` — служебные скрипты;
- `.tmp/`, `.tmp-*.txt`;
- PDF-сканы книг.

Их не нужно публиковать: они тяжёлые и/или содержат материалы, не предназначенные для распространения.

## Технические заметки

- Никакой серверной части: только статические файлы.
- Никакой сборки: данные лежат в `content/*.js` и `assets/`.
- Сохранения — в `localStorage` браузера, у каждого посетителя свои.
- Роутинг томов — hash-роутинг (`#/start`, `#/rules`, `#/tools/sheet`), поэтому прямые ссылки не требуют настройки 404.
- GitHub Pages чувствителен к регистру имён файлов — не переименовывайте папки `assets` и `content`.
